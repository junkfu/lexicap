## 1. 專案定位

一個 Chrome 擴充功能，讓使用者在 Netflix 觀看英文影片時，**以零中斷的方式**把不熟的單字與句子擷取下來，事後自動附上中文解釋，形成一本可搜尋、可回跳原片的個人單字筆記。

**一句話定義**：一本會自動長大的看片筆記本。

### 這不是什麼（重要）

- ❌ 不是即時翻譯工具（看片當下不顯示翻譯）
- ❌ 不是間隔重複／背誦系統
- ❌ 不是雙語字幕外掛

---

## 2. 使用者背景

- 母語：繁體中文，目標語言：英文
- 主要情境：晚間看 Netflix 影集，**字幕一律開英文**
- 內容以**英語原聲**為主
- 目前為 sideload（developer mode 載入）

---

## 3. 核心設計原則

1. **看片當下只擷取，不呈現任何需要閱讀的內容**
2. **擷取動作必須「零決策、零瞄準、零暫停」**
3. **timestamp 是系統的核心資產** —— 每一筆都要能回跳到那一秒
4. **資料必須可匯出**
5. **擴充不得改變使用者原本的觀看體驗** ← v0.2 新增

> 原則 5 是實作中學到的。曾經發生：隱藏原生字幕但 Overlay 沒畫出來 → 完全沒有字幕；用播放器 API 開關字幕 → 切回中文時位置被重置。現在的規則是：**任何接管都必須可完全還原，且失敗時一律退化成「跟沒裝擴充一樣」。**

---

## 4. 使用者流程

### 4.1 觀看時（Capture）

| 動作 | 結果 | 中斷程度 |
|---|---|---|
| 滑鼠點擊單字 | 存**該單字 + 所屬整句 + 前後句 + timestamp** | 零 |
| 按 `S` | 存當前正在播的整句 | 零 |
| 按 `A` | 存上一句 | 零 |

回饋：右下角 1 秒微型 toast（`已存 running` / `已存這句` / `已經存過了`）。

> **決策**：點單字時**整句一起存**，但**清單頁只顯示那個字**。
> 句子是富化的語境來源，也讓匯出的筆記有上下文；儲存成本為零，
> 而「顯示得清爽」用排版解決就好，不需要真的不存。

> **擴充只在英文字幕時接管。** 切到中文或關掉字幕 → 原生字幕正常顯示、Overlay 收起、熱鍵不攔按鍵，完全休眠。

### 4.2 背景（Enrich）

打開清單頁時，自動把 `enrichStatus === 'raw'` 的補上解釋。分批處理，每批完成即更新畫面。

> **為什麼不在 service worker 做**：Chrome 內建 AI API（Translator / Prompt）
> **在 Web Worker 與 extension service worker 中不可用**，官方說明是無法為
> worker 建立 responsible document 來檢查 Permissions Policy。
> 所以原計畫「SW 用 alarm 定時富化」對內建 AI 不成立。

### 4.3 事後（Review）

清單頁（點擴充圖示開啟）：

- 按影片分組，**組內新的排最上面**
- 搜尋（句子／單字／解釋／片名）
- `▶ 00:12:34` 一鍵回跳
- 「譯」按鈕 → 開 Google 翻譯並帶入內容
- 刪除、重新翻譯
- 匯出 Markdown / CSV

## 5. 系統架構

```
┌──────────────────── Chrome Extension (MV3 / WXT) ────────────────────┐
│                                                                       │
│  entrypoints/netflix-main.content.ts     world: MAIN, document_start  │
│    ├─ hook JSON.stringify → 注入 WebVTT profile                       │
│    ├─ hook JSON.parse     → 取得 $.result.textTracks                  │
│    ├─ 比對 player.getMovieId() 確認是當前這集                          │
│    ├─ 下載並回傳 WebVTT                                                │
│    └─ 每秒讀使用者選的字幕軌，決定要不要接管                              │
│           ↕ postMessage（lib/bridge.ts）                              │
│  entrypoints/netflix.content.ts          world: ISOLATED             │
│    ├─ 解析 WebVTT → Cue[]（lib/subtitles/vtt.ts）                     │
│    ├─ 自繪 Overlay（lib/overlay.ts）                                  │
│    ├─ 熱鍵 S / A（capture phase）                                     │
│    └─ chrome.runtime.sendMessage  ← 唯一的資料出口                     │
│           ↓                                                           │
│  entrypoints/background.ts               service worker              │
│    └─ Dexie / IndexedDB（唯一的 DB 持有者）                            │
│           ↓                                                           │
│  entrypoints/list/                       extension page              │
│    ├─ 清單、搜尋、回跳、匯出                                            │
│    └─ 富化：離線詞典 + Chrome 內建 Translator                          │
└───────────────────────────────────────────────────────────────────────┘
```

### 兩條架構鐵則

**1. DB 只能在 background / extension page 開啟。**
Content script 雖跑在 isolated world，但 storage API 用的是**宿主頁面的 origin**。在 content script 開 Dexie，資料會存進 `netflix.com` 底下，使用者清網站資料就全沒。

**2. Service worker 不得有跨事件的記憶體狀態。**
MV3 的 SW 閒置約 30 秒就終止。佇列就是 DB 裡 `enrichStatus === 'raw'` 的記錄本身。

## 6. 平台實作細節（Netflix）

> 以下全部經 [`spike/netflix-probe.js`](../spike/netflix-probe.js) 在真實播放頁驗證（2026-09-12）。
> 完整探勘記錄見 [`spike/FINDINGS.md`](../spike/FINDINGS.md)。**Netflix 改版時重跑 probe，不要猜。**

### 6.1 字幕取得：hook `JSON.parse`

```
$.result.textTracks        ← 字幕軌陣列（舊名 timedtexttracks，已改名）
$.result.movieId           ← 這份 manifest 屬於哪一集
track.downloadables        ← 下載點，以 profile 名為 key（舊名 ttDownloadables）
```

**為什麼不是 hook XMLHttpRequest**：manifest 走 **MSL 加密**，網路層看不到明文。但 Netflix 一定得用 `JSON.parse` 把它解出來 —— 這個 hook 點不依賴網路層實作、不依賴 React 結構、不依賴任何 selector，是最耐改版的。

**不要同時掛多個 hook 取先成功者** —— 失效時的除錯會變噩夢。掛一個，配明確的錯誤狀態。

### 6.2 取得 WebVTT 而非 TTML：hook `JSON.stringify`

在 manifest 請求送出前把 `webvtt-lssdh-ios8` 注入 profiles。實測命中兩個路徑，**兩個都要注入**：

- `$.params.profiles`
- `$.params.profileGroups[].profiles`

**必須 clone 後再改。** 直接對 Netflix 的物件 `push()` 會污染其內部狀態，實測造成 `TypeError: Cannot read properties of undefined (reading 'startTime')`。

WebVTT 的時間軸**直接就是秒**，不需要 TTML 的 tick 換算（1 秒 = 10,000,000 ticks，這是最經典的 off-by-10⁷ bug）。

### 6.3 一次播放會攔到多份 manifest ⚠️

Netflix 會預抓下一集與推薦內容的 manifest。實測一次播放攔到三份不同影片的（40 / 77 / 25 軌）。

**必須用 `player.getMovieId()` 比對，不符就丟棄。** 不做比對會偶發性地把別集的字幕掛到這集上 —— 因為只是偶發，極難查。

### 6.4 選軌規則

依分數排序：`closedcaptions` +4、`subtitles` +1、非 `isForcedNarrative` +2、有 WebVTT profile +1。並先過濾掉 `downloadables` 為空的軌（Netflix 是懶載入的，只有靠近使用者語言偏好的幾軌是滿的）。

**為什麼優先 CC 而非 subtitles**：實測同一集 CC 軌 368 句 vs subtitles 軌 260 句，**差 108 句** —— subtitles 軌為了閱讀速度被大幅精簡改寫。核心原則 3 是「回跳重聽原音」，**字幕與語音對不上是致命的**；音效描述可以 regex 剝除，被改寫過的台詞救不回來。

`languageDescription` 不可用來判斷語言 —— 實測有 `language: 'en'` 但描述是「關閉」的軌（那是 forced narrative 軌）。

### 6.5 字幕文字清理

```js
const SFX     = /\[[^\]]*\]|\([^)]*\)|♪/g;          // [door slams] (laughs) ♪
const SPEAKER = /^\s*-?\s*[A-Z][A-Z0-9 .'’-]{1,24}:\s*/;  // MAN: KURAPIKA:
```

**必須逐行清理** —— 說話者標籤只出現在行首，join 之後就抓不到。
同時要**解碼 HTML entity**（實測有 `&lrm;`）並剝除零寬／方向字元，否則會污染搜尋與 LLM 輸入。

每筆保留 `raw`（原始）與 `text`（清理後）。

**17% 的 cue 是純音效** —— 實測 368 句中 64 句清理後全空。所以擷取一律在「`text` 非空」的清單上操作；按 `S` 時若當下落在 `[roaring]` 上，往前找最近有台詞的句。

### 6.6 Overlay

- 掛在 `.watch-video` **內部**（掛外面全螢幕會消失），配 MutationObserver 在 React 重繪後重新掛載
- **渲染完全由 `video.currentTime` 驅動**，不觀察原生字幕 DOM
- 停留策略：**停到下一句出現**（取最後一個 `start <= 現在時間` 的句）。這是唯一完全可預測的規則，使用者不需在腦中維護計時器
- 只顯示一行（v0.1 曾顯示前一句，實際使用後移除）
- 滑鼠移入**凍結當前句**，影片繼續播
- `position: fixed`，不依賴宿主容器的定位脈絡；全螢幕時 fixed 相對於全螢幕視窗，兩種狀態都正確
- 控制列避讓：MutationObserver 監聽 `[data-uia="player"]` 的 `active` / `inactive`

### 6.7 遮蔽原生字幕：CSS，不是播放器 API ⚠️

```css
html.lexicap-active .player-timedtext { visibility: hidden !important; }
```

**不要用 `player.setTimedTextVisibility()`。** 實測用它開關之後，Netflix 會把字幕位置**重置**，不是還原成使用者原本的設定。

> v0.1 排除 CSS 方案的理由是「會跟 React 重繪打架」——**那個判斷只對「改元素的 inline style」成立**。stylesheet 裡的規則不受重繪影響，React 重建元素後規則照樣命中。兩種 CSS 做法被混為一談，導致選了侵入性更高的方案。

### 6.8 回跳：必須用 player API

```js
const api  = netflix.appContext.state.playerApp.getAPI();
const vp   = api.videoPlayer;
const pl   = vp.getVideoPlayerBySessionId(vp.getAllPlayerSessionIds()[0]);
pl.seek(300000);   // 參數是毫秒
```

**寫 `video.currentTime` 會被播放器覆寫**（讀取沒問題）。

清單頁回跳優先讓已開著該影片的分頁直接 seek，沒有才開新分頁。

### 6.9 影片後設資料

```js
pl.getMovieId()                                         // 集的 id
document.querySelector('[data-uia="video-title"]').innerText
```

`document.title` 只有 `'Netflix'`，沒用。片名**會跟著 Netflix UI 語言在地化**（存到的是中文片名），且**只在控制列顯示時才掛上 DOM** —— 取不到時沿用上次成功的值。

### 6.10 🔑 只用 `data-uia` 選 DOM

`default-ltr-iqcdef-cache-fntwn3` 那類是 CSS-in-JS 產生的雜湊 class，**Netflix 每次改版重建都會變**。`data-uia` 是 Netflix 自己的測試自動化屬性，是這個頁面上最穩定的識別面。

### 6.11 SPA 導航

Netflix 換集不重新載入 document，content script 不會重跑。**不能用「等一次、逾時放棄」的模型** —— v0.1 就是這樣，導致「從瀏覽頁按播放鍵進去」完全失效。

現在每秒檢查播放器，發現新的 `<video>` 就重新接上並清空舊字幕。熱鍵只註冊一次（放在重新接上的流程裡會累積監聽，按一次 `S` 存好幾筆）。

### 6.12 DRM 硬限制（設計時不可依賴）

- `canvas.drawImage(video)` 取得**黑畫面** → 無法截圖
- **無法擷取音訊** → 無法存原音片段

因此「回跳 timestamp」是唯一可行的原音重聽方案。

## 7. 資料模型

```ts
interface Capture {
  id: string;
  platform: 'netflix';
  videoId: string;          // player.getMovieId()
  videoTitle: string;       // 在地化片名

  startTime: number;        // 秒，核心欄位
  endTime: number;

  text: string;             // 原句（清理後）
  prevText?: string;        // 前後文，供富化判斷語境
  nextText?: string;

  word: string | null;      // 點選的單字；null 表示整句擷取
  captureType: 'word' | 'sentence' | 'selection';

  // 由富化填入
  translation?: string;     // 整句中譯
  wordMeaning?: string;     // 詞義
  lemma?: string;           // 原形，供分組與搜尋
  pos?: string;
  note?: string;

  enrichStatus: 'raw' | 'done' | 'failed';
  capturedAt: number;
}
```

Dexie 索引：`id, videoId, capturedAt, enrichStatus, lemma`

**同一個字重複擷取一律新增一筆，永不在寫入時合併。** Capture 是不可變的事件日誌，timestamp 是核心資產，寫入時合併就摧毀了語境。清單頁要分組的話在**讀取時**聚合。（防連按的去重只比對「同一句 + 同一個字」。）

## 8. 富化設計

### 8.1 現行：離線詞典（單字）+ Chrome 內建 Translator（句子）

| 擷取類型 | 處理 |
|---|---|
| 單字 | 查打包的離線英漢詞典，列出**所有義項** |
| 詞典查不到（人名、罕見字） | 退回 Chrome 內建 Translator |
| 整句 | Chrome 內建 Translator |

**零設定、離線、免費。**

**為什麼是詞典而不是機器翻譯**：MT 引擎對單一個字只會回**一個**它猜的意思，實測 `goal` → 籃、`Hunter` → 跡人。而它的介面就是 `translate(字串) → 字串`，**沒有任何地方能表達「這個字在這句裡是什麼意思」**。詞典則誠實地列出全部義項：

```
goal → n. 目標, 終點, 得分, 球門, 守門員；vi. 攻門, 射門得分
```

使用者自己一眼就能挑對的那個。對語言學習來說，誠實地呈現歧義比硬選一個有用。

**詞典資料**：[ECDICT](https://github.com/skywind3000/ECDICT)（MIT）依詞頻篩選 + OpenCC 轉繁體台灣用語 → 41,729 詞條 + 30,029 變化形，3.09 MB。
重建腳本：`scripts/build-dictionary.py`（需 `pip3 install opencc-python-reimplemented`）。

ECDICT 的 `exchange` 欄記錄動詞變化與名詞複數，所以 `ran` → `run`、`goals` → `goal` 自動轉導 —— **不需要任何 lemmatizer 函式庫**。

### 8.2 保留未接上：LLM 富化器

`lib/enrich/llm.ts` 是一份完整可用的實作（OpenAI 相容端點，同時支援 Ollama 與雲端），能做到現行方案做不到的事：**判斷該字在這句裡的意思**。

Prompt 已寫好規則：

> `wordMeaning` 必須是該字**在這個句子裡**的意思，不是字典上的第一個解釋。
> 例如 `"Yes, goal!"` 裡的 goal 是「抵達終點」，不是「目標」。

目前沒接上 UI。要啟用的話換進 `lib/enrich/index.ts` 的 `resolveEnricher()` 並補設定介面即可 —— 擷取與資料模型都不用動。這就是把富化抽成 `Enricher` 介面的用意。

## 9. 技術選型

### 9.1 採用

| 項目 | 選擇 | 理由 |
|---|---|---|
| 擴充框架 | **WXT 0.21** | Vite-based，file-based entrypoints；Plasmo 自 2025/09 未發版 |
| UI | React 19 + TypeScript | 清單頁 |
| 樣式 | **純 CSS** | 單一頁面規模下 Tailwind 沒有賺到它的重量 |
| 本地儲存 | **IndexedDB + Dexie 4** | `chrome.storage.local` 有 10MB 上限 |
| 單字解釋 | **離線詞典（ECDICT）** | 列出所有義項；零設定、離線、免費 |
| 句子翻譯 | **Chrome 內建 Translator API** | 支援 zh-Hant；零成本、離線 |

### 9.2 已否決（含理由）

| 方案 | 否決理由 |
|---|---|
| Tampermonkey 腳本 | 無法用 `chrome.storage` / 跨域 fetch |
| Electron / 桌面 App / 網頁 | Netflix 有 DRM |
| ts-fsrs / SM-2 間隔重複 | 不做背誦系統 |
| 克漏字 / 卡片題型 | 同上 |
| 依賴原生字幕 DOM | 字幕會消失、會被重繪 |
| 模擬點擊恢復播放 | race condition + 畫面閃動；已有 `video.play()` |
| **Cloudflare Workers proxy** | 富化改用本機方案後不需要任何 API key |
| **Chrome Prompt API（Gemini Nano）** | **只支援 en/ja/es/de/fr，不支援中文輸出** |
| **在 service worker 做富化** | Chrome 內建 AI API 在 worker 中不可用 |
| **用 `setTimedTextVisibility()` 遮字幕** | 切回時 Netflix 重置字幕位置（見 §6.7） |
| **wink-lemmatizer / compromise** | ECDICT 的 `exchange` 欄已涵蓋 |
| 後端抓字幕 | DRM + MSL 加密 |

### 9.3 曾否決後又採用

| 方案 | 說明 |
|---|---|
| **ECDICT 本地詞庫** | v0.1 因「即時查詢與詞頻過濾兩項功能已移除」而否決。但後來發現**需求不同**：需要的不是即時查詢，是「列出所有義項讓使用者自己挑」。這是 MT 引擎做不到的。 |

## 10. 已知限制

| 限制 | 說明 |
|---|---|
| **無法判斷語境詞義** | 詞典列出所有義項但不會說這句用哪個。需 LLM（§8.2） |
| **只支援 Netflix** | YouTube adapter 未實作 |
| **拖曳圈選未實作** | |
| **早期資料沒有句子** | 「點字只存單字」那版存的資料補不回語境 |
| **語言包首次下載需手勢** | Chrome 規定，不能自動開始。清單頁會顯示按鈕 |
| **Netflix 改版會壞** | 平台專屬邏輯集中在 `lib/netflix/` 與 MAIN world content script |

### M0 的驗證標準（仍待實際使用一週後檢視）

「一週擷取超過 N 筆」只量了輸入。用三個：

- **(a) 有擷取的觀看場次比例** —— >50% 才算習慣成立
- **(b) 有沒有在沒被提醒的情況下自己打開清單頁** ← **真正的死亡判定**
- **(c) 第 7 天單日擷取數 vs 第 1 天** —— 新鮮感衰減曲線

### YouTube（M3）的已知難點

- **timedtext 端點已強制要求 PoToken**（綁定 videoId，需 `&pot=` + `&c=WEB`）。自己重組 URL 會拿到 HTTP 200 空 body。**正解是 hook 播放器自身的請求**，它帶著合法 pot
- **MV3 的 `webRequest` 讀不到 response body**（`webRequestBlocking` 已移除，`filterResponseData` 是 Firefox-only）
- **ASR 字幕沒有標點與大小寫**，json3 是 rolling append 需去重。「整句」概念不成立
- SPA 換頁時 `ytInitialPlayerResponse` 不更新，要 hook `/youtubei/v1/player`
